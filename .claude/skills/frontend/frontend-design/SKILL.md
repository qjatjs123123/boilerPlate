# 화면 디자인 — 업무 시스템 디자인 기준

이 프로젝트의 화면은 **사내 업무 시스템**처럼 보여야 한다.
목표는 "눈에 띄는 화면"이 아니라 **신뢰감 있고, 정돈되고, 오래 써도 피로하지 않은 업무 화면**이다.
업무 실무자가 숫자와 문서를 정확하게 읽고 처리하는 것이 최우선이다.

---

## 시작 전 필수: 참고 이미지 먼저 보기

코드를 쓰기 전에 **반드시** 아래를 수행한다. 건너뛰지 않는다.

1. `.claude/skills/frontend/frontend-design/images/README.md` 를 읽어 이미지 목록을 확인한다.
2. 만들 화면과 비슷한 종류의 이미지를 **Read 도구로 열어 본다.** 어느 것이 맞는지 확실하지 않으면 전부 연다.
3. 이미지에서 뽑아낼 것: 색의 쓰임(어디에 주황을 쓰는지), 여백·정렬, 표·버튼·폼·배지 모양, 글자 크기 단계, 헤더·사이드바 배치.
4. 이미지는 **모양의 기준**이다 — 이미지 속 글자·데이터·로고를 그대로 베끼지 않는다.
5. 이미지의 색과 토큰(`globals.css`) 색이 약간 다르면 토큰을 따른다. 차이가 크면 사용자에게 알리고 토큰 수정을 제안한다.
6. `images/` 에 이미지가 없으면 "참고 이미지가 없어 글 기준으로 진행합니다" 를 한 줄 알리고 아래 원칙대로 진행한다.

## 0. 우선순위 (충돌 시 위가 이긴다)

1. **참고 이미지** — `images/` 의 스크린샷 (배치·모양·밀도 기준).
2. **앱 디자인 토큰** — `src/app/globals.css` 의 `--color-app-*` 와 shadcn 변수(`--primary` 등).
3. **shadcn/ui 부품** — `@/components/ui/*` (`react-convention.md` 「UI 라이브러리」).
4. 이 문서의 원칙.

> **예외 — 색은 이미지가 이기지 않는다.** 이미지는 배치·모양·밀도의 기준이고, 색은 2(토큰)와 이 문서 §2(주황 단일 강조, 삭제 = `destructive`)를 따른다. 이미지가 다른 서비스의 표현이라 위 원칙과 어긋나는 부분은 `images/README.md` 「따르지 않는 부분」에 적어 두었다.

## 1. 디자인 성격

| 지향 | 지양 |
|---|---|
| 신뢰·전문성·정확성 | 장난스럽거나 유행을 타는 스타일 |
| 흰 바탕 + 회색 톤 + **주황 한 가지 강조** | 여러 원색, 무지개 팔레트, 보라 그라데이션 |
| 넉넉한 여백, 정렬된 그리드 | 비대칭·겹침·대각선 배치 같은 실험적 레이아웃 |
| 표·필터·폼 중심의 밀도 있는 정보 배치 | 큰 일러스트·장식 위주의 랜딩 페이지형 화면 |
| 짧고 목적 있는 전환 효과 | 화려한 등장 애니메이션, 패럴랙스, 커스텀 커서 |
| 단색 배경 | 그라데이션 메시·노이즈·글래스모피즘 배경 |

## 2. 색

색은 **토큰으로만** 쓴다 — 16진수 하드코딩 금지 (`react-convention.md`).

| 역할 | 사용할 토큰 / 클래스 |
|---|---|
| 주 강조 (주요 버튼, 선택 상태, 포커스) | `bg-primary` · `text-primary` · `ring-ring` (= `app-orange-400`) |
| 강조 hover/active | `app-orange-500` |
| 제목 텍스트 | `text-app-heading` |
| 본문 텍스트 | `text-app-text-body` / `text-app-text` |
| 보조 텍스트·라벨·placeholder | `text-muted-foreground` (= `app-gray-500`) |
| 테두리·구분선 | `border-border` (= `app-border`) |
| 페이지 배경 / 영역 배경 | `bg-background` / `bg-app-bg-gray`, `bg-muted` |
| 링크 | `text-app-link` |
| 오류·삭제 | `text-destructive` · `bg-destructive` |

규칙:
- **주황은 화면당 "가장 중요한 행동 1개"에만.** 같은 화면의 나머지 버튼은 `outline`·`secondary`·`ghost` variant.
- **본문 글자를 주황으로 쓰지 않는다** — 흰 바탕 위 주황 글자는 대비가 낮아 읽기 어렵다. 주황은 면(버튼·배지·선택 표시)과 굵은 짧은 문구에만.
- 새 색이 꼭 필요하면 컴포넌트에 쓰지 말고 `globals.css` 의 `@theme` 에 `--color-app-*` 토큰을 먼저 추가한다.
- 차트는 주황 계열 + 회색 계열로 구성한다. 계열 구분이 많으면 회색 농도로 나누고, 강조할 계열 하나만 주황.

## 3. 글꼴·글자

- 글꼴은 현재 Next 기본값(Geist)이다. 디자인 킷 반입 후에만 **영문 Helvetica Neue + 한글 Noto Sans KR** 로 바꾼다 (`font.md`). 그 전에는 글꼴을 건드리지 않는다.
- 컴포넌트에서 `font-family` 를 따로 지정하지 않는다.
- 굵기는 300·400·500·600·700 만. 제목 600~700, 본문 400, 라벨 500.
- 크기 단계는 절제한다 — 페이지 제목 `text-2xl`, 섹션 제목 `text-lg`, 본문 `text-sm`~`text-base`, 보조 `text-xs`~`text-sm`.
- **숫자(금액·비율·건수)는 오른쪽 정렬 + `tabular-nums`** 로 자릿수를 맞춘다. 금액은 천 단위 쉼표.
- 모든 문구는 한국어, 존댓말 안내문 ("저장되었습니다", "항목을 선택해주세요").

## 4. 레이아웃

- 앱 뼈대는 `components/layout/AppShell` 을 쓴다. 페이지마다 헤더·사이드바를 새로 만들지 않는다.
- 페이지 구조는 **제목 → (설명 한 줄) → 필터/검색 → 본문(표·카드·폼) → 페이지네이션** 순서를 기본으로 한다.
- 간격은 Tailwind 4px 단위 (`gap-2`·`gap-4`·`gap-6`·`p-6`). 임의값(`p-[13px]`) 금지.
- 모서리는 `--radius`(0.375rem) 기준의 `rounded-md` 계열 — 과하게 둥근 알약 모양 금지.
- 그림자는 최소한 (`shadow-sm` 이하). 영역 구분은 그림자보다 **테두리 + 배경색 차이**로.
- 최대 너비를 정해 넓은 모니터에서도 표가 과하게 늘어나지 않게 한다 (예: `max-w-7xl mx-auto`).

## 5. 컴포넌트별 기준

| 부품 | 기준 |
|---|---|
| 버튼 | shadcn `Button`. 주요 1개 `default`(주황), 나머지 `outline`/`secondary`. 삭제는 `destructive` + 확인창(`AlertDialog`) |
| 표 | shadcn `Table`. 헤더 배경 `bg-muted`, 행 구분선 `border-border`, hover 시 옅은 회색. 숫자 열 오른쪽 정렬. 빈 목록은 "등록된 항목이 없습니다" 안내 행 |
| 폼 | 라벨은 입력칸 위, 필수 항목 표시, 오류는 칸 아래 `text-destructive text-sm` (`zod-usage` 스킬) |
| 상태 배지 | 작은 `rounded-md` 배지, 회색 기본 + 진행/완료 등 핵심 상태만 강조색 |
| 로딩 | shadcn `Skeleton` (스피너 남발 금지), 조회 경계는 `QueryBoundary` |
| 알림 | `lib/toast.ts` 래퍼 (`error-toast` 스킬) |
| 아이콘 | lucide-react, `size-4`(16px) 기본, 문구 옆 보조 역할. 아이콘만 있는 버튼엔 `aria-label` |

## 6. 움직임

- 상태 변화 피드백 정도만 — hover·focus 색 전환 `transition-colors`, 다이얼로그·드롭다운의 기본 열림 효과.
- 페이지 진입 연출, 스크롤 연동 효과, 반복 애니메이션은 쓰지 않는다.

## 7. 접근성

- 키보드만으로 모든 동작 가능 — 포커스 링(`ring-ring`)을 지우지 않는다.
- 색만으로 의미를 전달하지 않는다 (오류는 빨간색 + 문구, 상태는 색 + 글자).
- 입력칸마다 연결된 `<label>`.

## 금지

- ❌ 디자인 킷 컴포넌트를 수정하거나 같은 역할의 부품을 새로 만들기
- ❌ 색 하드코딩, 토큰에 없는 새 색 직접 사용
- ❌ 별도 CSS 파일·inline style (Tailwind 클래스만)
- ❌ 컴포넌트에서 글꼴 직접 지정, 외부 웹폰트 추가
